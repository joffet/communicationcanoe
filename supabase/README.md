# Pre-cutover migration history

Nothing in this directory is applied any more. It is kept as the provenance
record for the Drizzle schema, which was generated by replaying
`migrations/*.sql` in filename order — `packages/database/src/schema/index.ts`
cites these files by name, and `apps/realtime-bridge/src/workers/outbound-batch-worker.ts`
points at one for the outbound-batch design. Deleting them would turn those
citations into dangling references.

The live schema source of truth is `packages/database/src/schema/index.ts`,
with generated migrations in `packages/database/drizzle/` and the hand-written
bootstrap/function SQL in `packages/database/sql/` (see that folder's README
for run order).

- `migrations/` — the Supabase-era migration history, frozen at
  `20250701002400_tenant_reside_app_url.sql`. Read-only history: new schema
  changes go through `pnpm db:generate`, never here.
- `seed.sql` — still current, still the dev seed. It is plain `INSERT`s against
  tables that survived the cutover unchanged, so it applies fine to a
  PlanetScale database; only the tool that runs it changed. See the root
  README's Quick Start.

`config.toml` was removed with the `supabase` CLI devDependency: it only
configured the local Supabase Docker stack (`supabase start`), which stopped
being the dev database at the cutover.

Supabase itself is still a live dependency — `@supabase/supabase-js` for
Realtime pub/sub — but that is the hosted project's Realtime service, unrelated
to anything here.
